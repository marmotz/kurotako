# Drift Guard (`tako check`) — technical design

Design for the `tako check` command. Product decisions come from [overview.md](overview.md);
the primitives this feature builds on live in
[core-pipeline/technical.md](../core-pipeline/technical.md) (`run()`, `RunResult`,
`RunOptions`, the `Writer` seam, the `TakoError` hierarchy),
[cli/technical.md](../cli/technical.md) (`runCli()`, `ConsoleReporter`, `renderError`,
`loadConfig()` wiring) and [output-modes/technical.md](../output-modes/technical.md)
(`directoryWriter`, `packageWriter`, the `<ns>/<generatorName>/` layout, the
`// Generated by tako` banner and the `.gitattributes` marker).

## Starting point

- **No code exists.** `tako check` is a fifth command in the `@kurotako/cli` tree, already
  anticipated in [cli/technical.md §Consequences](../cli/technical.md) ("`tako check` …
  will be a fifth command in this same tree, reusing `ConsoleReporter`, `renderError`,
  `loadAndRun({ write: false })` and `RunResult.files` to diff against disk"). This
  document refines that sketch — in particular it replaces "`RunResult.files`" with a
  writer-computed **plan** so mode B works without duplicating the package layout.
- Toolchain unchanged (Bun workspaces, `tsc -b`, tsup, vitest, Biome, Node >= 24, **no
  `Bun.*`** — disk access via `node:fs/promises`).
- Upstream contracts consumed as-is: `loadConfig()` / `LoadResult` from
  [`@kurotako/config`](../config-system/technical.md); `run()` / `RunResult` / `Writer` /
  `selectWriter` / `TakoError` from [`@kurotako/core`](../core-pipeline/technical.md).
- Relevant design decisions (see [docs/architecture.md](../../../docs/architecture.md)):
  modes A / B; deterministic identifiers — the whole feature rests on byte-deterministic
  regeneration.
- Ordering: **post-v1 fast-follow** (overview). Depends on
  [core-pipeline](../core-pipeline/overview.md), [cli](../cli/overview.md) and
  [output-modes](../output-modes/overview.md) being fully implemented (all three writers +
  the banner/`.gitattributes` steps).

## Command surface

```
tako check [--config <path>]
```

- No `--watch`, no `--namespace` / `--generator` filter, no `--json`, no `--diff`
  (overview: whole output, list of drifting files only). `--config` is the shared global
  arg, forwarded verbatim to `loadConfig({ cwd: process.cwd(), configPath })` like every
  other command ([cli/technical.md §Global option](../cli/technical.md)).
- **Exit codes**: `0` when the output on disk matches what a fresh `generate` would
  produce; `1` on any drift; `1` on any `TakoError` from `loadConfig` / `run` (invalid
  config, invalid IR, driver failure — same top-level handler as the other commands).
- Human output on **stderr** via `ConsoleReporter`; `stdout` stays clean (consistent with
  [cli/technical.md §Reporter](../cli/technical.md), leaves room for a future `--json`).

## Mechanism — the `Writer.plan()` seam

`tako check` never writes to disk and never uses a temporary directory. It asks the
pipeline for the **exact set of files a `generate` would write** (absolute path +
content), then compares that set against the filesystem.

`RunResult.files` alone is not enough: it is the mode-A-shaped virtual tree
(`<ns>/<generatorName>/…`), whereas mode B remaps paths into
`<pkgDir>/src/…` and adds a synthesized `package.json` / `tsconfig.json` /
`tsup.config.ts`. Reproducing that mapping in the CLI would duplicate `packageWriter`.
Instead, the writer that already owns the layout computes it.

### `Writer` interface addition (core `writer/types.ts`, task [#20](../../tasks/20-core-writer.md))

```ts
export interface PlannedFile {
  path: string       // absolute
  content: string    // exact bytes a generate would write (banner already applied)
}

export interface Writer {
  write(input: WriteInput): Promise<string[]>
  plan(input: WriteInput): Promise<PlannedFile[]>   // NEW: same layout as write(), no disk I/O
}
```

- `directoryWriter.plan`: maps each `VirtualFile` to
  `resolve(output.dir, vf.path)` and appends `<output.dir>/.gitattributes` with the
  `GITATTRIBUTES` constant. No wipe, no `mkdir`, no `writeFile`.
- `packageWriter.plan`: the **deterministic subset** of `packageWriter.write` — group by
  namespace, strip the `<ns>/` prefix into `<pkgDir>/src/…`, synthesize
  `<pkgDir>/package.json` (frozen `version: "0.0.0"`, sorted `peerDependencies`,
  fixed key order), `<pkgDir>/tsconfig.json`, `<pkgDir>/tsup.config.ts`,
  `<pkgDir>/.gitattributes` and `<packagesDir>/.gitattributes`. **No tsup build** (`dist/`
  is a build product, out of scope — overview) and **no `pm install`** (a check must not
  mutate `node_modules` / the lockfile).
- Implementation: `write()` is refactored to `plan()` then "materialise" — for
  `directoryWriter`, `plan()` is the pure half and `write()` = wipe + `mkdir -p` +
  `writeFile` over the plan; for `packageWriter`, `write()` = write the plan + tsup build +
  install. One layout code path, no drift between `plan` and `write`.

### `run()` amendment (core `run.ts` / `types.ts`, tasks [#15](../../tasks/15-core-types-and-contracts.md), [#21](../../tasks/21-core-run.md))

```ts
export interface RunOptions {
  logger?: Logger
  signal?: AbortSignal
  write?: boolean          // default true
  plan?: boolean           // NEW: default false
}

export interface RunResult {
  ir: IR
  order: string[]
  files: VirtualFile[]
  artifacts: Record<string, GeneratorArtifact>
  plan?: PlannedFile[]     // NEW: present iff opts.plan === true
}
```

When `opts.plan` is `true`: `run()` executes steps 1 → 5c unchanged (parse, merge,
`assertIR`, generator DAG, collect, synthesize root barrels, `applyBanner`), then calls
`selectWriter(config.output).plan({ files, output })` and returns the result as
`RunResult.plan`. `write` is forced off and the `afterEmit` hook does **not** fire
(`plan` implies no emission). A `TakoError` from any earlier step propagates as usual —
an invalid schema fails `tako check` exactly as it fails `tako generate`.

## The comparison (`packages/cli/src/diff.ts`)

```ts
export type DriftKind = 'modified' | 'missing' | 'orphan'
export interface DriftEntry { kind: DriftKind; path: string }   // path relative to rootDir

export async function comparePlanToDisk(args: {
  plan: PlannedFile[]
  roots: string[]              // dirs to scan for orphans (absolute)
  ignore: (absPath: string) => boolean
  rootDir: string              // for relativising the reported paths
}): Promise<DriftEntry[]>
```

1. **Expected vs disk.** For each `PlannedFile`:
   - file absent on disk → `missing`;
   - `readFile(path, 'utf8')` !== `content` → `modified`;
   - equal → not reported.
   Comparison is **exact bytes**, no line-ending or trailing-newline leniency: generators
   emit `\n` and a final newline deterministically, so any difference is real drift.
2. **Orphan scan.** Walk each entry of `roots` recursively; every regular file whose
   absolute path is not in the planned set and not rejected by `ignore` → `orphan`.
   - **Directory collapse**: a directory whose entire subtree is orphan (no planned file
     under it) is reported once as `orphan <dir>/` instead of one line per file — this is
     what a stale mode-B package dir or a removed namespace looks like.
3. Sort the entries by `path`, then by `kind`. Return them.

### Roots and ignore rules per mode

- **Mode A** (`output.dir`): `roots = [output.dir]`. `tako` is the exclusive owner and
  wipes it every run, so anything not planned is drift. `ignore` rejects nothing (a `.git`
  or `node_modules` inside the output dir would itself be a misconfiguration).
  - If `output.dir` does not exist at all, `check` prints a single line
    `output directory <dir> does not exist — run tako generate` and exits `1`, rather than
    dumping one `missing` line per planned file. (Expected when the output dir is
    `.gitignore`d and not regenerated — that project runs `generate` first.)
- **Mode B** (`packagesDir`, `scope`): `packagesDir` may also hold hand-written packages,
  which must **not** be flagged. `roots` is the set of package directories `tako` owns:
  - every `<pkgDir>` for a namespace in the current config;
  - plus any sibling directory under `packagesDir` whose `package.json` carries the
    `"//": "Generated by tako. Do not edit."` marker (same marker as the
    `OutputNotGeneratedError` wipe guard —
    [output-modes/technical.md §Errors](../output-modes/technical.md)) but whose namespace
    is no longer in the config → the whole directory collapses to one `orphan` line.
  - `ignore` rejects `**/dist/**` and `**/node_modules/**` under every root.

## Output & reporter

One line per drifting file, aligned, on stderr:

```
tako  drift detected

  modified  pg/zod/user.schema.ts
  missing   pg/angular/order.form.ts
  orphan    pg/zod/legacy.schema.ts

3 files differ from a fresh generate. Run `tako generate`.
```

- Paths are relative to `rootDir` (the config-file directory).
- In sync → a single `tako  output is in sync` line, exit `0`.
- The drift list is printed by `check` itself (like `generate`'s summary line), not by a
  `run()` phase log. `ConsoleReporter` only prefixes `tako ` and colourises.
- No `--verbose`, no per-file content, no unified diff (overview). A follow-up `--diff`
  flag is possible later; it would be the first output flag in the CLI and is explicitly
  out of scope here.

## `afterEmit` / formatting hooks are not run

`tako check` skips the `afterEmit` hook (it operates on a real directory; there is none).
**Consequence — decided**: a project that formats generated code through an `afterEmit`
Biome/Prettier hook will see `tako check` report spurious drift, because the committed,
formatted tree will not match the unformatted planner output.

The contract is therefore: **generators must emit deterministic, already-formatted code**
(they already aim for byte-determinism —
[core-pipeline/technical.md §Determinism](../core-pipeline/technical.md),
[generator-zod/technical.md §Determinism](../generator-zod/technical.md)). An `afterEmit`
formatter is a convenience for the `generate` path only and is documented as incompatible
with `tako check`. This is recorded in [overview.md](overview.md) and flagged for
[core-pipeline/technical.md §Hooks](../core-pipeline/technical.md) and
[docs/architecture.md](../../../docs/architecture.md) (doc-only reconciliation).

## Determinism dependency

`tako check` is only meaningful if `run()` is a pure function of `(config, schema files)`.
[core-pipeline/technical.md §Determinism](../core-pipeline/technical.md) already lists
drift-guard as the reason for: sorted-namespace parse order, stable topological generator
order, key-order-preserving `filterIR`, path-sorted aggregated tree, and no timestamps /
absolute paths in generated content. [output-modes/technical.md §Determinism](../output-modes/technical.md)
adds: frozen `version: "0.0.0"`, sorted `peerDependencies`, fixed `package.json` key
order. No new determinism requirement is introduced here — this feature is the consumer
those guarantees were written for.

## Alternatives considered

- **`tako check` reads `RunResult.files` and maps paths itself** (the cli/technical.md
  sketch). Rejected: works for mode A but forces the CLI to reproduce `packageWriter`'s
  `src/` remap + `package.json` / `tsconfig` / `tsup.config` synthesis, which would drift
  from the real writer. The `Writer.plan()` seam keeps one source of truth.
- **Generate into a temporary directory, then diff two trees.** Rejected (user choice: an
  in-memory comparison). It would also re-run `afterEmit` — which we deliberately do not —
  and in mode B `packageWriter` runs `pm install` at the **workspace root**, mutating the
  real `node_modules` / lockfile; a check must have zero side effects.
- **A separate `Planner` seam distinct from `Writer`.** Rejected: `plan()` and `write()`
  share every line of layout logic; splitting them invites exactly the plan/write
  divergence this feature cannot tolerate.
- **Run `afterEmit` against the plan.** Rejected: `afterEmit` is defined over a written
  directory ([core-pipeline/technical.md §Hooks](../core-pipeline/technical.md)), not a
  virtual tree; honouring it would require the temp-dir approach.
- **`tako generate --check` flag instead of a subcommand.** Rejected in
  [overview.md](overview.md): the intent is distinct and reads clearly in hook / CI logs.

## Consequences — amendments this feature forces

### `core-pipeline/technical.md` — additive, delivered by **this feature's task [#51](../../tasks/51-core-writer-plan.md)**, not folded into #15/#20/#21

The v1 core tasks ship without `plan`: [#15](../../tasks/15-core-types-and-contracts.md)
declares `RunOptions` / `RunResult` in their v1 shape, [#20](../../tasks/20-core-writer.md)
ships `Writer` with `write()` only, [#21](../../tasks/21-core-run.md) wires `run.ts`
collect → write → `afterEmit`. This feature (post-v1 fast-follow) then layers on:

- `Writer` interface gains `plan(input: WriteInput): Promise<PlannedFile[]>`; `PlannedFile`
  is a new exported type (#51).
- `directoryWriter` is refactored so `plan()` is the pure layout half and `write()` builds
  on it; `write()` behaviour (unconditional wipe, `.gitattributes`) is unchanged (#51).
- `RunOptions.plan?: boolean` and `RunResult.plan?: PlannedFile[]` (#51); `run.ts` calls
  `selectWriter(output).plan(...)` after step 5c when `opts.plan`, forces `write: false`,
  skips `afterEmit` (#51).
- §Hooks: note that drift-guard does not run `afterEmit`; a formatting hook there is
  incompatible with `tako check` (doc-only reconciliation).
- The `--emit-ir` / `--dry-run` list in §"What stays out of this feature" gains `plan`
  as a sibling primitive the CLI builds `tako check` on (doc-only reconciliation).

### `output-modes/technical.md` — additive, delivered by **this feature's task [#52](../../tasks/52-output-package-writer-plan.md)**

[#50](../../tasks/50-output-package-writer.md) ships `packageWriter` with `write()` only.
This feature then adds:

- `packageWriter` implements `plan()` — the deterministic subset (`src/` remap +
  `package.json` + `tsconfig.json` + `tsup.config.ts` + `.gitattributes`), no tsup build,
  no `pm install`. `write()` is rebuilt as `plan()` + build + install (#52).
- §"drift-guard/overview.md (noted for that feature)" is now realised here: the mode-B
  diff scope (`src/` + manifest + generated config files, ignore `dist/`) is implemented
  by `packageWriter.plan` + the `diff.ts` ignore rule.

### `cli/technical.md` (new task, see below)

- New command `commands/check.ts` + `diff.ts` (`comparePlanToDisk`). Wires a `check`
  entry into the citty tree in `cli.ts` with the shared `--config` arg.
- `check.ts`: `loadConfig()` → `run(config, { logger: reporter, plan: true })` → build the
  `roots` / `ignore` for the config's output mode → `comparePlanToDisk` → print + set
  `process.exitCode`.
- No change to `renderError` / the top-level `TakoError` handler — a check that fails to
  even regenerate exits `1` through the existing path.
- The §Consequences "drift-guard" bullet in `cli/technical.md` is updated from the
  `RunResult.files` sketch to the `plan: true` mechanism.

### `docs/` (doc-only, not this phase)

- [docs/vision.md](../../../docs/vision.md#out-of-scope-for-v1) — "CI / Drift Guard" stays
  out of v1; it is the first post-v1 backlog item.
- [docs/architecture.md](../../../docs/architecture.md) — add `tako check` to the CLI
  command list; note the `afterEmit`-formatter incompatibility.

## What stays out of this feature

- **`dist/` comparison, real package versions, registry publish** — `dist/` is a tsup
  build product, not deterministic generator output (overview).
- **`--diff` / `--json` / `--verbose` output** — [cli](../cli/overview.md) minimal-output
  rule; possible later.
- **Partial / `--namespace` checks** — whole output only, consistent with "no incremental
  regeneration in v1".
- **A pre-commit hook wiring / lefthook entry in a consumer repo** — documentation, not
  code shipped by `tako`.
- **The `Writer` / `run()` primitives themselves** — [core-pipeline](../core-pipeline/technical.md)
  and [output-modes](../output-modes/technical.md) own them; this feature adds the `plan`
  method and option.

## Tests (vitest, colocated)

- `directoryWriter.plan`: returns absolute paths under `output.dir` + `.gitattributes`,
  content byte-identical to what `write()` produces, touches no disk.
- `packageWriter.plan`: `<pkgDir>/src/…` prefix stripped, `package.json` /
  `tsconfig.json` / `tsup.config.ts` / `.gitattributes` present, `version: "0.0.0"`,
  sorted `peerDependencies`; **no** `dist/` entry; no subprocess spawned.
- `run({ plan: true })`: returns `RunResult.plan`, `afterEmit` never fires, nothing
  written; an invalid IR still throws the same `TakoError`.
- `comparePlanToDisk` (temp dir):
  - identical tree → no entries;
  - one file edited → `modified`; one file deleted → `missing`; one extra file → `orphan`;
  - a whole extra directory → single collapsed `orphan <dir>/`;
  - mode-B: a hand-written sibling package (no tako marker) is **not** flagged; a stale
    marked package dir is one `orphan`; `dist/` and `node_modules/` ignored.
- `commands/check.ts` (fake config + in-memory drivers, mirroring the other CLI command
  tests):
  - in-sync project → exit 0, "output is in sync";
  - a tampered generated file → exit 1, the file listed as `modified`;
  - a removed generated file → exit 1, `missing`;
  - mode A with a non-existent `output.dir` → exit 1, the single "does not exist" line;
  - a config whose schema is invalid → exit 1 via `renderError` (not a drift report).
