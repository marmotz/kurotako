# kurotako

kurotako is a modular framework for synchronizing TypeScript schemas from the data model
down to frontend forms, through a validation layer. In a stack like NestJS + Prisma +
Angular, the data schema is defined once but the validation DTOs and the frontend types /
forms are duplicated by hand or generated by tools locked onto a single stack (typically
Prisma → Zod → React). kurotako is a generic, interchangeable pipeline instead: one
`parser` input, N `generator` outputs, wired by a dependency graph. Angular is a
first-class output target, and several parsers can run in parallel, isolated by namespace.

The CLI binary is `tako`. Packages are published under `@kurotako/*`.

> **Status: design phase.** The seven packages are scaffolded empty (a single exported
> `version` const and one trivial test each) so the whole toolchain runs end to end. Real
> content lands in the downstream features.

## Requirements

- **Node.js >= 24**
- **Bun >= 1.4** (installer and script runner)
- Consumer-side **TypeScript >= 5.5**

## Getting started

```bash
bun install
bun run build
```

## Scripts

| Script | Action |
|---|---|
| `bun run build` | Build every package (`tsup`, dual ESM + CJS) |
| `bun run typecheck` | `tsc -b` across the workspace |
| `bun run test` | `vitest run` across the workspace |
| `bun run lint` | `biome check .` |
| `bun run format` | `biome format --write .` |
| `bun run release` | `changeset publish` |

`dist/` is not committed: run `bun install && bun run build` once before using a package
from source.
